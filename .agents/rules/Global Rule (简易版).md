### 1. 技术栈约束 (不得偏离)

- **后端**：Java 17 + Spring Boot 3 + MyBatis-Plus。
- **JSON**：必须用 **Fastjson2**。
- **管理端**：Vue 3 (Setup 语法) + Element Plus + Pinia。
- **用户端**：Nuxt 3 + Tailwind CSS。

### 2. 开发底线 (强制执行)

- **Bean 安全**：定义 Bean（尤其是 Redis 配置）必须显式命名，严禁出现 `BeanDefinitionOverrideException` 冲突。
- **异步幂等**：所有 RocketMQ 消费者必须包含**幂等性校验**逻辑。
- **校验先行**：接口入参必须用 `@Validated`，严禁裸奔。
- **环境隔离**：密钥、密码禁止硬编码，统一写在 `.env` 或 `yml` 配置文件中。
- **非必要不修改**：尽量不动跟本模块不强相关的代码

### 3. AI 协作逻辑
- **不懂就问**：面对需求不明显的地方要问我。但不是什么都问我，不影响的情况下自己解决。
- **先计划后动手**：修改多文件前，必须先列出计划（Plan）。
- **TypeScript**：前端代码必须强制使用 TypeScript，禁止使用 `any`。
- **有自由度**：单一模块的实现确定计划后，在不影响最后成效的情况下自己决定实现顺序

### 4. 文档更新

- **及时更新文档**：完成一系列功能后，如果我直奔下一个主题，你要询问我要不要更新document下的需求、功能迭代文档，以便后续开发和更新。
- **自我学习避免重复错误**：将自己犯的错和疏忽精简表达放入document文件夹下，自己建一个文档及时更新。
- **自动缩短上下文**：每次回复的时候精简总结上一条消息的重点，以时间和第几次回复为文件名将重点放在document文件下，未来每次回复都根据这个文件进行。

## 5. 执行计划与自动化（新增）

为保证规则长期可执行、便于 CI 校验和团队协作，新增以下可执行约束与自动化实现：

- 校验脚本：`tools/verify_rules.ps1`（PowerShell） — 做为本地/CI 的前置检查，包含：
	- 检查 `backend/pom.xml` 是否声明 `fastjson2` 依赖；
	- 检查 `front-ui` / `admin-ui` 是否存在 `tsconfig.json`（确认前端使用 TypeScript）；
	- 在 `front-ui` 下查找 `.js` 源文件并标记为需迁移为 TypeScript 的警告；
	- 简易扫描 Java 控制器中的 `@RequestBody` 用法，报告缺少 `@Validated` 注解的可疑用例（人工复核）；

- CI 集成建议（后续）：把 `tools/verify_rules.ps1` 集成到 CI（GitHub Actions / ADO），在 PR 检查时运行，阻止违反约定的提交进入主干。

- 文档与学习：每次在仓库 `document/` 下写入短摘要（格式：`YYYY-MM-DD_N_短标题.md`），并在 PR 描述中引用该摘要文件。

实施规则时的注意：脚本为“辅助检测”工具，不能完全替代人工复核；对于脚本标记的项（如 `@RequestBody` 未标注 `@Validated`），请人工确认并修正。
