# 📑 ACG_Space 动漫内容与数字谷子集换社区 V3.0 产品需求文档 （V2.0→V3.0 演进） (PRD)

## 一、 产品概述与定位

一款集“高质量番剧检索、动漫资讯阅读”与“数字谷子集换及实体周边核销”于一体的二次元社区。系统维持纯 PGC（官方单向发布）的内容生产模式，结合 SSG 静态站点生成技术保障 SEO。在此基础上，引入高并发抽赏引擎与 O2O 实体流转机制，通过积分系统驱动用户活跃，形成“获取积分 -> 抽赏/交易 -> 实体核销”的完整商业闭环。

## 二、 全局基础与核心概念

### 2.1 用户基础规则

- **账号状态体系：** 维持游客 (Guest)、注册用户 (User)、会员用户 (VIP) 的基础分级机制。
- **全局积分制：** 积分是全站唯一的流通硬通货，获取途径包括每日签到、发布评论（默认 +5 分）、评论被赞（默认 +2 分）等日常活跃行为。

### 2.2 数字资产与实体 O2O 规则（V3.0 核心）

- **有限库存发售（防超卖）：** **【确定需求】** 所有的数字抽赏（如：限定卡池、拼图盲盒）均为**有限绝对库存**，抽完即绝版。系统采用强一致性策略，当库存不足以满足用户抽卡请求（如十连抽时库存仅剩 3 个）时，系统直接拦截并提示“库存不足”，不允许透支抽取。
- **资产通缩与交易税：** **【确定需求】** 在集市的任何二手交易中，系统官方将强制收取卖家挂单总价 **1%** 的积分作为交易手续费（向下取整，最低 1 积分），用于对冲每日发出的活跃积分，防止通货膨胀。
- **虚实状态机流转：** **【确定需求】** 数字资产（成品 SSR）具有**双重属性**。它既可以在集市中无限次倒买倒卖，也可以由最终持有者发起“实体核销”，将数字数据销毁，转化为一条真实的物流发货订单。一旦发起核销申请，该资产将被冻结，不可再流转。

## 三、 前台核心功能流转 (用户端 - Vue3/Nuxt3)

### 3.1 基础内容消费大厅

- **动漫资源库：** 按年份、类型、状态进行复合筛选，展示详情及外部播放/下载渠道，含 VIP 专属线路拦截。
- **资讯博客区：** 展示文章列表，支持底部点赞与楼中楼评论，显示评论者头衔徽章。

### 3.2 抽赏中心 (Gacha Hub)

- **奖池展示：** 轮播展示当前开放的限定卡池，实时显示剩余总库存量及各奖品余量。
- **高并发抽卡：** 提供“单抽”与“十连抽”按钮。
  - **异常提示：** 积分不足时提示充值/做任务；库存不足时提示“卡池已被掏空”或“剩余库存不足以进行十连抽”。
  - **成功反馈：** 抽中后触发开箱动画，获得的物品实时存入个人数字背包。

### 3.3 记忆工坊与数字背包 (Assets & Synthesis)

- **数字背包：** 可视化展示用户当前持有的所有资产。
- **合成共鸣：** 展示官方合成图鉴。用户集齐对应碎片后，点击合成。系统在毫秒级锁定碎片资源，合成成功后销毁碎片，生成成品 SSR。
- **实体核销请求：** **【核心流转】** 针对成品 SSR 提供"申请发货"入口。用户填写收货信息，确认后该资产在背包中被标记为"已核销/待发货"，脱离数字流转体系。

### 3.4 跳蚤市场 (Flea Market)

- **挂单大厅：** 瀑布流展示全站玩家上架的资产。
- **卖家上架：** 用户设置积分售价上架资产，前端需透明展示扣除 1% 手续费后的实际到手积分。上架后资产状态变更为"挂单锁定中"。
- **买家秒杀：** 支付积分买下挂单。交易成功后实时转移资产所有权，买家扣分，卖家加分（扣除 1% 交易税后）。

### 3.5 兑换中心 (Redeem Hub) - V3.0 新增

- **商品展示：** 展示当前可兑换的实物商品列表，包含商品图片、名称、所需 UR 碎片数量、所需积分数量、库存余量。
- **兑换流程：** 用户点击商品后填写收货信息（收货人、电话、省市区、详细地址），确认后扣除对应 UR 碎片和积分，生成兑换订单。
- **资源校验：** 兑换前系统校验用户 UR 碎片余额和积分余额，不足则拦截并提示。
- **订单追踪：** 用户可在订单列表查看兑换订单状态（待发货/已发货/已完成）及物流信息。

## 四、 后台功能需求 (管理端 - RuoYi-Vue)

### 4.1 基础内容与社区管控

- **PGC 管理：** 动漫词条、博客文章、播放线路及广告位的全生命周期管理。
- **积分策略引擎：** 配置发布评论、点赞等行为的奖惩额度。

### 4.2 电商与资产管控中台 (V2.0 新增)

- **商品与图鉴字典库：** 录入盲盒、碎片、成品 SSR 的基础数据及合成配方。
- **抽赏发售控制器：** 创建活动，设定总发售库存量、单品库存分布、活动时间。
- **交易风控与日志中心：** **【核心监控】** 监控 RocketMQ 事务回查日志，展示异常交易单据，提供人工补偿干预入口。
- **O2O 实体物流调度台：** **【核心闭环】**
  - 展示所有用户提交的“实体发货申请”单据（状态：待发货）。
  - 支持管理员录入快递公司与物流单号，流转状态为“已发货”。
- **兑换商品管理：** **【V3.0 新增】**
  - 管理可兑换实物商品列表，包含商品名称、图片、所需 UR 碎片/积分数量、库存、上下架状态。
  - 支持新增、编辑、删除商品，图片支持 Base64 粘贴上传。
- **兑换订单管理：** **【V3.0 新增】**
  - 查看用户兑换订单列表，包含订单号、商品信息、收货信息、订单状态。
  - 支持录入物流公司与物流单号，更新订单状态为"已发货"。

## 五、 技术架构与非功能性需求

### 5.1 前端架构

- 采用 SSG (静态站点生成) 保障资讯内容的 SEO，资产流转等高频交互采用 CSR (客户端渲染) 结合 WebSocket 实现实时状态同步。

### 5.2 高并发与分布式交易架构设计 (V3.0 核心技术壁垒)

- **强一致性抽赏引擎 (Redis + Lua)：**
  - 基于 `有限库存规则`，使用 Lua 脚本在 Redis 内部原子化执行“校验库存余额”、“校验用户积分余额”、“扣减库存”、“冻结积分”等一系列操作。
  - 严格保证不超卖，库存不足时直接抛出异常返回前端。
  - 扣减成功后，通过 RocketMQ 发送异步消息，下游消费者负责真正落库（扣减 MySQL 积分流水、生成盲盒记录、增加背包资产）。
- **多资产并发锁定机制 (Redisson MultiLock)：** 在“碎片合成”场景中，利用 Redisson 的联锁功能同时锁定参与合成的所有碎片资源，杜绝并发篡改或重复利用。
- **交易最终一致性保障 (RocketMQ Transaction Message)：** 针对二手集市交易，以“扣减买家积分并生成交易快照”为本地事务，利用 MQ 的回查机制（关联 `biz_transaction_log` 表），确保异步转移资产、增加卖家（含税扣除）积分等动作一定能被执行，实现高可用和资金安全。

### 5.3 数据库设计预演 (核心新增表)

- `biz_item_dict`: 全局物品图鉴表。
- `biz_user_asset`: 用户数字资产背包表 (`user_id`, `item_id`, `status` [正常/交易锁定/合成锁定/已核销])。
- `biz_market_order`: 集市挂单与交易订单表。
- `biz_transaction_log`: RocketMQ 事务日志回查表。
- `biz_user_address`: 用户收货地址管理表。
- `biz_redeem_product`: 兑换商品表 (V3.0 新增，包含商品名称、图片、UR碎片/积分消耗、库存、状态)。
- `biz_redeem_order`: 兑换订单表 (V3.0 新增，包含订单号、用户ID、商品信息、收货信息、物流信息、订单状态)。
- `biz_user_fragment`: 用户碎片表 (V3.0 新增，记录用户持有的各类碎片数量)。
