### 一、 后端核心架构 (Backend Scaffold)

基于 **Spring Boot 2.7.x / 3.x + Java 17** (依托 RuoYi-Vue 底座进行增强)。

#### 1. 基础增强依赖

RuoYi 自带了 MyBatis，但为了更高效的 CRUD 和应对复杂的资产查询，建议升级为 **MyBatis-Plus**。

- **mybatis-plus-boot-starter**: 替换原生 MyBatis，提供强大的条件构造器（Wrapper），方便在集市挂单中进行复杂的多条件筛选。
- **hutool-all**: 必不可少的 Java 工具包，处理日期、加密、集合、HTTP 请求等，能省去大量造轮子的时间。
- **fastjson2** 或 **jackson**: 高性能 JSON 解析，用于在 Redis 缓存和 MQ 消息体中序列化复杂的盲盒/资产对象。

#### 2. 高并发与分布式锁 (V3.0 核心武器)

为了实现“十连抽 Lua 脚本原子扣减”和“多碎片合成联锁”，必须引入以下组件：

- **spring-boot-starter-data-redis**: Spring 官方 Redis 客户端，用于执行 Lua 脚本（如：`redisTemplate.execute(redisScript, keys, args)`）进行库存预扣。
- **redisson-spring-boot-starter**: **极其重要！** 这是 V3.0 的核心依赖。利用其提供的 `RLock` 处理常规并发，利用 `RedissonMultiLock` 解决“碎片合成”时同时锁定多个碎片资源（碎片 A、B、C）的防重复消耗问题。

#### 3. 分布式消息队列 (V3.0 事务核心)

为了解决跳蚤市场的“二手碎片交易”一致性，以及抽卡后的“异步发奖”落库：

- **rocketmq-spring-boot-starter**: 阿里开源的金融级 MQ。
  - 使用 `RocketMQTemplate` 发送普通异步消息（抽卡后异步增加资产、流水）。
  - 使用 `@RocketMQTransactionListener` 实现本地事务回查，保障集市交易（买家扣款、卖家发货）的**最终一致性**。

### 二、 前端核心架构 (Frontend Scaffold)

#### 1. C 端用户前台 (Nuxt 3 / Vue 3)

面向普通用户的社区门户、抽赏中心和跳蚤市场，需要极高的 SEO 和首屏速度。

- **核心框架**: `nuxt` (v3) - 提供 SSG/SSR 渲染能力。
- **UI 框架**: `tailwindcss` (作为原子化 CSS，方便定制二次元风格 UI)，搭配无头组件库如 `headlessui/vue` 或轻量级库 `naive-ui`。
- **状态管理**: `@pinia/nuxt` - 全局管理用户的登录状态、当前积分余额和数字背包数据。
- **网络请求**: 优先使用 Nuxt3 内置的 `$fetch` (基于 `ofetch`)，配合自定义的拦截器（Interceptor）处理 JWT Token 携带和全局未登录拦截。
- **动画库 (抽卡必备)**: `gsap` 或 `@vueuse/motion` - 用于实现“十连抽”开盲盒时的炫酷入场动画和碎片合成时的粒子特效。

#### 2. B 端后台管理系统 (Vite / Vue 3)

面向管理员的 PGC 内容发布、商品图鉴录入和 O2O 物流发货管理（RuoYi-Vue3 原生脚手架已包含大部分）。

- **核心框架**: `vue` (v3) + `vite`。
- **UI 框架**: `element-plus` - 极其适合构建复杂的 B 端表单和数据表格（如图鉴配置、订单管理、MQ 死信队列监控面板）。
- **状态管理**: `pinia`。
- **路由**: `vue-router`。

### 三、 运维与基础设施 (Infrastructure - Docker Compose)

为了让你的全栈项目能一键运行起来，你的 `docker-compose.yml` 至少需要编排以下几个核心容器：

1. **mysql:8.0**: 存储持久化业务数据，支持 ACID 事务（注意配置好字符集 `utf8mb4` 以支持二次元颜文字和特殊符号）。
2. **redis:7.x**: 承担首页缓存、字典缓存，以及最关键的 Lua 脚本执行环境**和**分布式锁服务。
3. **rocketmq-namesrv & rocketmq-broker**: 消息队列集群的核心。对于开发环境，以单 Master 模式运行即可。
4. **rocketmq-dashboard** (可选但强烈建议): RocketMQ 的可视化面板，在开发期间用来实时监控事务消息是否成功投递、死信队列是否有积压，是 Debug 的绝佳工具。
