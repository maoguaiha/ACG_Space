# 🏗️ ACG_Space 动漫社区与数字谷子集换平台 - 技术架构设计文档 (V2.0)

## 一、 架构设计目标

本系统旨在构建一个兼顾**低运营成本、高响应速度、极佳 SEO 收录**以及**高扩展性**的垂直内容社区。在 V2.0/V2.1 阶段，系统全面融入了数字资产流转、O2O 实体核销业务与实物兑换系统，新增以下核心设计目标：  

1. **动静分离与极速首屏：** 核心内容页具备强 SEO 能力，支持毫秒级首屏加载。  

2. **后台敏捷开发：** 最小化管理端开发成本，高度复用现有企业级轮子。  

3. **高并发强一致性安全：** 在面临"限定谷子十连抽"、"多并发碎片合成"等极高瞬时流量时，利用 Redis+Lua 与分布式锁保障绝对的防超卖与防资产复制。

4. **分布式交易最终一致性：** 引入事务消息体系，保障二手跳蚤市场中跨服务（扣款、结算、资产转移）的数据最终一致。

5. **实物兑换闭环：** 用户可使用 UR 碎片或积分兑换实物商品，系统自动扣除资源并生成订单，管理员可追踪物流状态。

## 四、 核心技术方案设计

### 4.1 混合渲染与 SEO 方案 (Nuxt 3 SSG + CSR)

开发打包时，Nuxt 3 预先生成公开内容的静态 HTML 文件并上传至 OSS[cite: 3]。搜索引擎爬虫抓取时，无需等待 JS 执行即可获取完整内容[cite: 3]。真实用户加载静态骨架后，通过 CSR 异步拉取个人资产、盲盒剩余库存等高频变化数据[cite: 3]。当管理员修改了番剧信息，通过 Webhook 触发页面的重新生成并覆盖旧文件[cite: 3]。

### 4.2 基于 RocketMQ 的高并发与事务引擎

1. **互动积分异步削峰：** 用户提交评论后，系统立刻返回 200 OK，同时向 RocketMQ 发送消息，由消费者异步执行计算规则并更新总积分[cite: 3]，同时记录流水至 `biz_user_points_log` 表[cite: 3]。
2. **集市交易最终一致性 (V2.0)：** 玩家在跳蚤市场购买资产时，系统向 RocketMQ 发出 Half-Message。本地事务负责扣减买家积分并写入 `biz_transaction_log` 回查日志。若本地事务成功，MQ 投递消息给下游执行“转移资产并给卖家加分（扣除 1% 税）”。结合 MQ 的 `CheckLocalTransaction` 机制，彻底杜绝系统宕机造成的资损。

### 4.3 Redis Lua 防超卖与 Redisson 分布式锁

- **有限库存十连抽：** 彻底摒弃 MySQL 扣库存。用户触发十连抽时，后端向 Redis 注入 Lua 脚本，原子化完成“判断奖池剩余量 -> 判断积分余额 -> 预扣库存 -> 预扣积分”。若库存不足以完成抽卡，脚本直接拦截并抛出异常，实现毫秒级强一致性防超卖。
- **MultiLock 多资产合成保护：** 玩家合成“成品 SSR”瞬间，系统调用 Redisson 的 `MultiLock`，将玩家选中的多个碎片（如 碎片A、碎片B、碎片C）对应的 Redis Key 全部锁定。只有全量锁定成功才执行合成操作，防止恶意并发请求将一块碎片重复熔炼。

## 五、 核心数据库规范与建模约束

基于 RuoYi 框架的规范，所有业务表均需遵循以下设计约束[cite: 3]：

1. **公共字段标配：** 所有业务表必须包含 `create_by`, `create_time`, `update_by`, `update_time`, `remark` (备注)[cite: 3]。
2. **逻辑删除控制：** 必须包含 `del_flag` 字段，严禁物理删除数据，便于后期审计和恢复[cite: 3]。
3. **主键策略：** 采用单机发号器或 Snowflake 算法生成全局唯一的 `bigint` 作为主键[cite: 3]。
4. **V2.0/V2.1 核心业务表结构：**
   - `biz_item_dict`: 全局物品图鉴表（盲盒、碎片、成品属性）。
   - `biz_user_asset`: 数字背包表（记录 `user_id`, `item_id`, `status`。其中 status 严格划分：正常/交易锁定/合成锁定/已核销）。
   - `biz_transaction_log`: MQ 事务日志回查表（记录全局事务号与执行状态）。
   - `biz_delivery_order`: O2O 实体发货订单表（记录核销资产 ID 与物流信息）。
   - `biz_redeem_product`: 兑换商品表（V2.1 新增，记录商品名称、图片、UR碎片/积分消耗、库存、状态）。
   - `biz_redeem_order`: 兑换订单表（V2.1 新增，记录订单号、用户ID、商品信息、收货信息、物流信息、订单状态）。
   - `biz_user_fragment`: 用户碎片表（V2.1 新增，记录用户持有的各类碎片数量）。
