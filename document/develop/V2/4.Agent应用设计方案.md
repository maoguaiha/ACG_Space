# ACG Space — 用户端 AI 助手（Agent 应用）设计方案 V1.0

> 状态：设计稿（待确认后进入实现）
> 日期：2026-07-27
> 范围确认结论：
> - 定位：**用户端对话式 AI 助手**（落点：Nuxt 3 用户端）
> - 模型：**云端大模型 API**（OpenAI 兼容协议）
> - 能力：**纯 RAG 问答**（检索增强，不调用后端写接口、不执行任何业务动作）

---

## 1. 背景与目标

ACG Space 已是成熟的动漫内容与数字谷子集换社区，具备：抽赏、合成、背包、跳蚤市场、兑换、订单、番剧库（Bangumi 接入）、站内信（`BizMessage`/`ConversationVO`）等完整能力。

当前用户面临两类痛点：
1. **规则复杂**：抽赏保底、碎片合成（10N→1SR）、积分、UR 兑换、物流核销等机制，新用户难以快速理解。
2. **找番困难**：番剧库日益增长，用户想要"类似 XX 的番""治愈系推荐"时缺乏自然语言入口。

**目标**：在用户端增加一个常驻的 AI 助手（对话式），基于社区自有知识库做 RAG 问答：
- 解答平台规则、玩法、活动；
- 基于番剧库做自然语言推荐与答疑（"这是什么番""有什么机战番推荐"）；
- 引导操作（"怎么兑换实物"→ 给出步骤 + 页面入口）；
- **不**做任何写操作、不触发抽赏/合成/下单，纯咨询，安全边界清晰。

## 2. 整体架构

```
┌─────────────────────────── 用户端 (Nuxt 3) ───────────────────────────┐
│  pages/agent/index.vue  (聊天页, 适配 浅色/深色/粉色 三主题)            │
│  components/agent/ChatWindow.vue / ChatMessage.vue / ChatInput.vue      │
│  composables/useAgentApi.ts  (fetch + ReadableStream 消费 SSE 流)      │
│  └─ 经 Nuxt Server 代理 server/api/agent/chat.post.ts (转发 SSE)        │
└───────────────────────────────────┬──────────────────────────────────┘
                                     │ HTTPS (SSE text/event-stream)
┌───────────────────────────────────▼──────────────────────────────────┐
│  后端 (Spring Boot 3, com.ruoyi.project.agent)                         │
│  AgentController (/api/agent/**)  → SseEmitter 流式返回                 │
│  AgentChatService  (编排：检索→拼Prompt→流式LLM→落库)                   │
│  AgentKnowledgeService (知识库切片/向量化/重建索引)                     │
│  AgentConversationService (会话/消息持久化, 绑用户)                     │
│  LlmClient (OpenAI 兼容 Chat+Embedding, 显式命名 Bean)                 │
│  ├─ 知识库检索：InMemoryEmbeddingStore (启动时从 MySQL 载入)            │
│  └─ 业务数据只读查询：BizAnimeMapper / 规则文案表 (仅 SELECT)           │
└───────┬───────────────────────────┬───────────────────────────────────┘
        │ OpenAI 兼容 API            │ MySQL                   │ Redis
        ▼                           ▼                          ▼
   云端大模型 (Chat+Embedding)   agent_conversation /        (会话缓存/
                                  agent_message /             限流计数,
                                  agent_knowledge(含向量)      复用现有)
```

**为什么这样分**：
- 复用现有 `BangumiApiClient` 的 HTTP 范式与 `RestTemplate`/`WebClient` 经验，但 LLM 走独立 `LlmClient`（需流式，用 `WebClient`）。
- 检索默认走 **内存向量索引 + MySQL 持久化**（社区语料规模 < 1 万段，余弦相似度足够快），不引入新中间件；Redis 向量（RediSearch）作为可选升级路径。
- 所有请求必须登录（`SecurityUtils.getUserId()` 绑定用户），不进 `permitAll`。

## 3. 技术选型与依赖

| 关注点 | 推荐方案 | 说明 |
|--------|----------|------|
| LLM 编排 | **langchain4j 0.34+**（Spring Boot Starter） | 原生支持 OpenAI 兼容、Embedding、内存向量库、流式 `TokenStream`；Java 17/Spring Boot 3 兼容。若要极致可控可改自研 `WebClient` 客户端（见 §4.4）。 |
| Chat 模型 | `qwen-plus` / `glm-4-flash` / `deepseek-chat`（OpenAI 兼容） | 推荐**同一家同时提供 chat + embedding**，避免双供应商。 |
| Embedding 模型 | `text-embedding-v3`(通义) / `embedding-3`(智谱) / `text-embedding-3-small`(OpenAI) | 维度 768~1536，存为 `LONGTEXT` JSON 数组。 |
| 向量检索 | `langchain4j` `InMemoryEmbeddingStore`（HNSW） | 启动时从 `agent_knowledge` 表载入内存；管理端"重建索引"按钮触发重新向量化。 |
| 流式协议 | SSE (`text/event-stream`) + `SseEmitter` | 后端 MVC 环境标准做法。 |
| 前端流消费 | `fetch` + `ReadableStream`（非 `EventSource`，因需 POST 带 body） | Nuxt server 路由代理 SSE 规避 CORS。 |
| 序列化 | **Fastjson2**（既有约束）；雪花 ID 转字符串 | 严格遵守。 |
| 限流 | 复用 **Resilience4j**（已有 `@RateLimiterAndCircuitBreaker`） | 对 `/api/agent/chat` 加限流防刷。 |
| 密钥 | 仅存 `.env` / `application.yml`（不硬编码） | `llm.api-key`、`llm.base-url`、`llm.chat-model`、`llm.embed-model`。 |

> **关键知识**：DeepSeek **没有** embedding 接口。若选 DeepSeek 做 chat，必须搭配另一个 embedding 供应商（智谱/通义/OpenAI）或本地 BGE（Ollama）。**最简方案 = 通义或智谱一家打通 chat+embedding**。

### 4.2 数据模型（新增 3 张表，遵循 BaseEntity 审计字段约定）
```sql
-- 会话表
CREATE TABLE agent_conversation (
  id BIGINT PRIMARY KEY,
  user_id BIGINT NOT NULL,
  title VARCHAR(100),
  create_by VARCHAR(64), create_time DATETIME, update_by VARCHAR(64), update_time DATETIME, remark VARCHAR(500), del_flag CHAR(1) DEFAULT '0',
  INDEX idx_user (user_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

-- 消息表
CREATE TABLE agent_message (
  id BIGINT PRIMARY KEY,
  conversation_id BIGINT NOT NULL,
  role VARCHAR(20) NOT NULL,        -- user / assistant / system
  content LONGTEXT NOT NULL,
  tokens INT,
  create_by VARCHAR(64), create_time DATETIME, update_by VARCHAR(64), update_time DATETIME, remark VARCHAR(500), del_flag CHAR(1) DEFAULT '0',
  INDEX idx_conv (conversation_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

-- 知识片段表(含向量)
CREATE TABLE agent_knowledge (
  id BIGINT PRIMARY KEY,
  source VARCHAR(50),              -- anime / rule / faq
  ref_id BIGINT,                   -- 关联 BizAnime.id 等
  title VARCHAR(200),
  content LONGTEXT NOT NULL,       -- 切片文本
  embedding LONGTEXT,              -- JSON 浮点数组
  create_by VARCHAR(64), create_time DATETIME, update_by VARCHAR(64), update_time DATETIME, remark VARCHAR(500), del_flag CHAR(1) DEFAULT '0'
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```
> 注：遵循 point.md 第 11 条，历史表无冲突；新增表均带 `create_by/create_time/update_by/update_time/remark/del_flag`；审计字段在 Controller 显式 set（项目无全局 MetaObjectHandler）。雪花 ID 走字符串。

### 4.3 核心流程（RAG + 流式）
1. 前端发 `POST /api/agent/chat`：`{conversationId?, message}`。
2. `AgentChatService`：
   - 新会话则建 `AgentConversation`；
   - 持久化 user 消息；
   - `embed(message)` → 在 `InMemoryEmbeddingStore` 取 Top-K（如 5）相似片段；
   - 组装 System Prompt（角色定义 + 安全边界：你是 ACG Space 官方助手，只回答社区相关，不执行任何操作）+ 检索到的上下文 + 历史（最近 N 轮）；
   - 调用 `StreamingChatLanguageModel`，逐 token 通过 `SseEmitter` 推送 `data:{json}`；
   - 流结束：拼接完整回答，持久化 assistant 消息，更新 `conversation.title`（首轮用前 20 字）。
3. 异常：超时/限流/模型错误 → 推送 `event:error` 并落库。

### 4.4 LlmClient（显式命名 Bean，示例核心）
```java
@Configuration
public class AgentLlmConfig {
    @Bean("llmChatModel")                       // 显式命名, 防 Bean 冲突
    public StreamingChatLanguageModel chatModel(@Value("${llm.base-url}") String url,
                                                @Value("${llm.api-key}") String key,
                                                @Value("${llm.chat-model}") String model) {
        return OpenAiStreamingChatModel.builder()
                .baseUrl(url).apiKey(key).modelName(model).build();
    }
    @Bean("llmEmbeddingModel")
    public EmbeddingModel embeddingModel(...) { /* 同 baseUrl, embed-model */ }
    @Bean("agentEmbeddingStore")
    public EmbeddingStore store() { return new InMemoryEmbeddingStore(); }
}
```
> 若不用 langchain4j：自研 `LlmClient` 用 `WebClient` 调 `/v1/chat/completions`（`stream:true`）与 `/v1/embeddings`，手动解析 SSE。控制力更强、零额外依赖，但需手写切片/相似度。

### 4.6 安全与质量
- 端点走登录校验（`SecurityUtils`），**不**加 `permitAll`。
- 复用 `@RateLimiterAndCircuitBreaker` 防刷与熔断。
- 入参 `@Validated`（message 非空、长度上限）。
- 系统 Prompt 内置安全边界，拒绝执行/投资建议，越权话题引导至人工客服。

### 5.2 流式消费（关键）
```ts
// useAgentApi.ts
export function streamChat(payload: AgentChatReq, onToken: (t: string) => void, onDone: () => void) {
  return fetch('/api/agent/chat', { method: 'POST', body: JSON.stringify(payload), headers: { 'Content-Type': 'application/json' } })
    .then(r => r.body!.getReader()).then(reader => {
      const dec = new TextDecoder(); let buf = ''
      const pump = (): Promise<void> => reader.read().then(({ value, done }) => {
        if (done) return onDone()
        buf += dec.decode(value, { stream: true })
        buf.split('\n\n').forEach(block => {
          const line = block.replace(/^data:/, '').trim(); if (line) onToken(JSON.parse(line).content)
        })
        return pump()
      })
      return pump()
    })
}
```

## 7. 知识库内容规划（RAG 语料）
| 来源 | 切片方式 | 示例 |
|------|----------|------|
| 平台规则文档 | 按小节切 300~500 字 | 抽赏保底机制、碎片合成比例、UR 兑换流程、积分获取方式 |
| 番剧库 `BizAnime` | 每部番一部一条 + 标签 | 标题/类型/简介/评分，支持"类似推荐"（向量近邻） |
| FAQ | 一问一答一条 | "怎么提现积分""订单多久发货" |
| Bangumi 缓存 | 热门条目补充 | 番剧别名、制作公司、季度 |

> 索引构建：`AgentKnowledgeService.buildIndex()` 遍历来源→切片→调 embedding→写 `agent_knowledge`→载入 `InMemoryEmbeddingStore`。管理端触发或启动时自动。

## 8. 实施路线图（分阶段，每阶段可独立验收）
- **Phase 0 选型与依赖**：引入 langchain4j（或确认自研）；加 `.env` 配置；写 `AgentLlmConfig`。
- **Phase 1 数据层**：3 张表 DDL + 实体 + Mapper + XML（含审计字段、雪花 ID 字符串化）。
- **Phase 2 知识库**：切片/向量化服务 + 启动加载 + 管理端重建索引接口。
- **Phase 3 对话服务**：RAG 编排 + SSE 流式接口 + 会话/消息持久化 + 限流接入。
- **Phase 4 用户端 UI**：聊天页 + 流式渲染 + 三主题适配 + 历史会话列表。
- **Phase 5 管理端（可选）**：知识库管理页。
- **Phase 6 质量保障**：单测（RAG 检索命中、SSE 完整性）、三主题自测、Resilience4j 限流压测、pre-commit 通过。
- **Phase 7 部署**：Railway 变量注入 `llm.*`、SQL 迁移脚本提交、文档更新。

> 按 AGENTS.md：每阶段代码 `git commit`（不直推）；跨 5+ 文件/架构调整已在此方案确认。

## 10. 风险与规避
| 风险 | 规避 |
|------|------|
| 模型幻觉答错规则 | 强约束 System Prompt + 仅基于检索片段作答 + 关键规则附原文来源 |
| API Key 泄露 | 仅 `.env`/yml，严禁硬编码；Railway 用变量注入 |
| 流式中断/超时 | SSE 心跳 + 全局 30s 超时 + 错误事件兜底 |
| 语料过期（规则变更） | 管理端"重建索引" + 规则文档变更时同步触发 |
| 向量库内存占用 | 社区语料规模小；升级路径用 Redis 向量 / pgvector |
| 限流失控成本 | Resilience4j 限流 + 单用户并发会话上限 |
