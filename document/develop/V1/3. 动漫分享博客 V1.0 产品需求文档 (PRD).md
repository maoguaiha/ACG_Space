# 📑 动漫分享博客 V1.0 产品需求文档 (PRD)

## 一、 产品概述

### 1.1 产品定位

一款集“高质量番剧检索、动漫资讯阅读、同好交流互动”于一体的垂直类内容社区。采用纯 PGC（官方单向发布）的内容生产模式，结合 SSG 静态站点生成技术，在保证低运营成本与极佳 SEO 的同时，通过积分名望体系驱动用户互动，并为未来的商业化（广告、会员）预留底层支持。

### 1.2 目标用户与使用场景

- **找番用户：** 通过分类导航或搜索，快速获取动漫信息及播放/下载渠道。
- **漫评读者：** 阅读深度的动漫解析与业界资讯。
- **社区活跃者：** 在喜欢的动漫和文章下发表评论，通过互动获取积分，提升账号头衔。

------

## 二、 全局规则说明

### 2.1 账号与权限状态

- **游客态 (Guest)：** 可浏览所有公开的动漫词条、文章和评论，可点击常规外部播放链接。触发点赞、评论、专属链接点击时，唤起登录/注册弹窗。
- **注册用户 (User)：** 拥有基础资料和积分账户，可进行点赞、评论、追番操作。
- **会员用户 (VIP)：** 拥有特殊标识，可通过校验访问隐藏的“VIP专享线路”和“专属文章”。

### 2.2 广告位全局规则

前端页面不硬编码任何推广内容。所有广告位预留标准骨架屏组件（如：长条Banner 1200x100，侧边栏矩形 300x250）。数据由后端统一接口下发，若无有效广告物料，则该区块自动折叠或展示默认提示语。

## 三、 前台功能需求 (用户端 - Vue3/Nuxt3)

### 3.1 首页 (Home)

- **顶部导航：** 包含 Logo、动漫库、资讯博客、搜索框、用户头像/登录入口、发表文章、主题色切换，私信。
- **轮播推荐区：** 展示后台配置的头条漫评或热门番剧（兼作顶级广告位）。
- **近期更新/新番导视：** 列表展示最近更新的动漫资源。

### 3.2 番剧库 (Anime Library)

- **分类检索页：** 支持按「年份」（如 2026、2025）、「类型」（热血、异世界、治愈）、「状态」（连载中、已完结）进行复合筛选；支持搜索。
- **动漫详情页：**
  - **基础信息：** 海报图、番剧名称、原版名称、开播日期、声优阵容、剧情简介。
  - **播放线路导航：** 以按钮组形式提供外部跳转链接。
  - **用户互动：** 收藏/追番按钮、评分展示（星级）。
  - **底部评论区：** 挂载通用评论组件。

### 3.3 我的追番

- **文章列表页：** 按发布时间倒序排列，展示封面图、标题、摘要、阅读量、评论数。
- **文章详情页：**
  - 支持富文本与 Markdown 格式渲染。
  - 支持文章底部点赞。
  - 底部挂载通用评论组件。
  - 侧边栏预留广告位/相关文章推荐。

### 3.4 社区 

- **文章列表页：** 按发布时间倒序排列，展示封面图、标题、摘要、阅读量、评论数。
- **用户列表页：** 可以搜索，按热度排序。
- **文章详情页：**
  - 支持富文本与 Markdown 格式渲染。
  - 支持文章底部点赞点踩。
  - 底部挂载通用评论组件。

### 3.5 个人中心与互动组件

- **通用评论组件：** 支持发布文字评论、楼中楼回复。展示评论者头像、昵称及**当前头衔徽章**。
- **个人中心仪表盘：**
  - 展示基本信息、VIP 状态。
  - 展示**当前总积分**与下一等级进度条。
  - **足迹模块：** 追番列表、我的评论记录、历史点赞。

### 3.5 个人中心与互动组件

- **通用评论组件：** 支持发布文字评论、楼中楼回复。展示评论者头像、昵称及**当前头衔徽章**。

- **用户管理：** 包含账号状态控制（封禁/解封）。

## 五、 技术架构与非功能性需求

### 5.1 前端渲染与 SEO (Vue3 + Nuxt3 SSG)

- **构建策略：** 采用静态站点生成（SSG）。动漫详情页和文章页等重 SEO 内容，在构建时直接生成 HTML 文件。
- **数据更新机制：** 采用增量静态生成（ISR）理念。当后台修改了某部番剧的信息或发布了新文章时，触发对应页面的重新构建，并同步至云存储/CDN。
- **动态数据注入：** 用户相关的动态状态（如当前是否已点赞、积分头衔、实时评论列表）在静态页面加载完成后，由客户端（CSR）发起异步请求获取并渲染。

### 5.2 后端架构设计

- **底层框架：** 采用 **RuoYi-Vue** (Spring Boot + Vue3) 企业级快速开发框架。直接复用其完善的权限管理（Spring Security）、部门/角色划分、代码生成器以及系统日志模块，极大降低管理端的开发工作量。
- **分布式组件引入：**
  - **缓存层 (Redis)：** 用于缓存首页推荐列表、分类标签字典以及高频访问的动漫元数据。需注意序列化配置，确保复杂对象（如嵌套的分类和线路列表）能正确存取。
  - **异步削峰 (RocketMQ)：** 积分系统的核心技术选型。前台用户提交评论后，系统立刻返回成功状态。同时发送一条消息至 RocketMQ，由消费者在后台异步执行“计算积分规则”、“累加用户总分”、“更新等级头衔”以及“记录积分变动流水”的繁重业务逻辑，保障高并发下的接口响应速度。

### 5.3 数据库设计预演 (核心表预留)

- `biz_anime`: 动漫主表（包含基础信息）。
- `biz_anime_route`: 播放线路表（与主表一对多关联，含 VIP 标识）。
- `biz_article`: 博客文章表。
- `biz_comment`: 统一评论树表（采用 `parent_id` 维护层级，关联业务 ID 和类型）。
- `biz_user_points_log`: 积分变动流水表（用于追溯和未来的兑换对账）。
