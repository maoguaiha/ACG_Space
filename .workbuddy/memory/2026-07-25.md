# 2026-07-25

## front-ui Railway 部署失败修复

### 问题
front-ui 在 Railway 上部署失败，24 次重试均 "service unavailable"，健康检查从未通过。

### 根因分析
1. 首页 `pages/index.vue` 在 SSR 阶段发起 3 个后端 API 调用（番剧列表、日历、精选）
2. Node.js fetch 默认无超时，后端不可达时 SSR 无限 hanging
3. 健康检查路径 `/` 触发 SSR，后端不可达 → SSR 永远不返回 → 超时

### 修复
1. **`composables/useApi.ts`**: 添加 SSR 请求超时 8s + `retry: 0`，防止 hanging
2. **`pages/index.vue`**: `useAsyncData` 调用加 `.catch()` 兜底为空数组，防止 SSR 崩溃
3. **`railway.json`**: 清理 startCommand（移除硬编码 URL 和冗余 HOST），healthcheckTimeout 降至 300s
4. **`package.json`**: 添加 `engines` 字段约束 Node >=18

### 上线后注意
- 需要在 Railway Variables 中设置 `NUXT_API_INTERNAL_BASE` 指向后端 URL
- 如果后端未部署或 URL 不对，首页会显示空数据/骨架屏，但不会 502

## 第二轮修复：Nixpacks → Dockerfile

### 问题
Nixpacks 自动选了 `nodejs_24`（忽略 .nvmrc 的 22），16/16 健康检查全挂，服务器可能根本没启动。

### 修复
1. **新建 `front-ui/Dockerfile`**: 多阶段构建，Node 22-alpine，`NODE_OPTIONS="--max-old-space-size=384"`（512MB 容器中给 V8 留余量）
2. **新建 `front-ui/.dockerignore`**: 排除 node_modules/.output/.nuxt
3. **新建 `front-ui/server/routes/health.ts`**: Nitro 纯静态健康检查端点 `/health`（不依赖 SSR、不调后端），返回 `{ status: 'ok' }`
4. **`front-ui/railway.json`**: builder 改为 DOCKERFILE，healthcheckPath 改为 `/health`，timeout 降为 120s

## 第三轮修复：Docker 运行时优化

### 问题
Docker 镜像构建成功但进程始终不启动。本地测试确认服务器正常（`Listening on http://[::]:3000`）。

### 修复
1. **`Dockerfile`**: 去掉 start.sh 包装，改用 `ENV HOST=0.0.0.0` + `ENV NITRO_HOST=0.0.0.0` 直接设环境变量
2. **`nuxt.config.ts`**: 加 `nitro.preset='node-server'` 确保构建输出不受环境影响
3. **`railway.json`**: 恢复 `startCommand: "node .output/server/index.mjs"` 确保覆盖 Docker CMD

## 第四轮修复：API 代理中间件拦截所有请求（真正的根因！）

### 发现
Railway 日志显示 `Listening on http://0.0.0.0:8080`，服务器**确实启动了**。

### 根因
`server/middleware/api-proxy.ts` 的 `defineEventHandler` 没有路径守卫。`/health` 被代理到 `http://localhost:18083/api/health` → 后端不可达 → 502。

### 修复
加 `if (!event.path.startsWith('/api-proxy')) return`，只拦截代理路径，其余走正常路由。
